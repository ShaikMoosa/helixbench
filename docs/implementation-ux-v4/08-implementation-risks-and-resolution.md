# Implementation risks, resolved policies and remaining validation

## Ready to implement

The authority choice, native stack, local-first scope, two-click measure, identity policy, tombstone/dependency rule, non-blocking feedback and typed-molecule routing have explicit defaults in this specification. Engineers can begin foundation tasks without another product questionnaire.

## Engineering prerequisites

Before adopting proposed identity/hash/parser dependencies, verify their MSRV/license/platform compatibility with the installed Rust/GPUI build and commit Cargo.lock changes. UUID v4 generation and SHA-256 APIs were checked against primary library documentation; dependency choice is proposed, not an installed-code claim.

## Scientific gate

Independent scientific-method validation is required for stronger scoring/analysis claims and new numeric behavior. Preserve existing algorithms and tests; do not “fix” scientific output to match a Figma number.

## Collaboration gate

Remote reviewers, shared permissions, actual request delivery, sync and organization accounts are a separate product/backend decision. The current implementation remains local. A Reviewer A screen is a workflow fixture and must not send external messages.

## Accessibility gate

The focus/error/panel patterns are specified. A native runtime review must verify semantics, screen-reader exposure, keyboard order, contrast at rendered sizes and status announcements. Do not claim WCAG conformance from Figma alone.

## Prototype routing gate

Some legacy reference frames and operation-content examples remain in the Figma file. Use the normative intent/state contract and canonical frame references, not every copied reaction literally. In particular, avoid unnecessary dirty guards for read-only tools and mandatory modal success steps for routine actions.

## Performance gate

No new hard maximum or latency guarantee is asserted without measurement. Capture memory, responsiveness, cancellation latency, parsing throughput and table/map scaling on declared datasets and Windows hardware before setting release performance budgets.

## Document maintenance

Treat this bundle as a versioned specification. When code or Figma changes, update the source revision/hashes, feature status, canonical frame map, test results and decision log together. This snapshot does not silently track future external changes.
